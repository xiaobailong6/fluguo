## 2. 动效方案，请选一档

单位均为毫秒。以下是设计目标，尚未实机体验验证。

| 动效 | 当前 | A：利落 | B：均衡，推荐 | C：舒缓 |
|---|---:|---:|---:|---:|
| 页面/弹层进入 | 480 | 240 | **320** | 400 |
| 页面/弹层退出 | 340 | 160 | **220** | 280 |
| Tab 页面与导航胶囊 | 460 | 260 | **340** | 400 |
| 滚动顶底栏、区域高度变化 | 560 | 300 | **400** | 480 |
| 首页大卡片内容进入 | 560 | 300 | **400** | 480 |
| 首页大卡片内容退出 | 400 | 200 | **260** | 320 |

- **A：利落。** 强调快速操作，过渡可见但收尾很快，适合频繁切换页面。
- **B：均衡。** 缩短当前的等待感，仍保留明显过渡；比直接减半更接近现有视觉风格。
- **C：舒缓。** 尽量保留现有从容节奏，只做温和提速。

### 三档共同保持不变

- 按压反馈 **100ms**、普通状态反馈 **160ms**。
- 主动回顶继续使用按距离计算的 **450–850ms**，不与短距离页面过渡混改。
- 通知停留时间、播放器控制栏自动隐藏时间、网络超时均不调整。
- 不新增用户设置开关，选定一档后作为统一默认值。
- `disableAnimations` / `accessibleNavigation` 的现有降级规则继续保留；首页大卡片写死的时长同步接入公共规则，避免漏掉减少动态效果设置。

## 3. 性能优化方案

### P1. 批量下载控制合并持久化

**当前问题：** [controlBatch](<E:/Github Local/fluguo/native/core/app_download_collections.go:80>)逐项调用单任务控制。每一项都可能复制、排序、编码整个下载索引并同步落盘，单批最多 500 项。

**实施方式：**

1. 批量去重、校验任务和来源权限，保留现有 `Completed/Failures` 逐项结果及输入顺序语义。
2. 暂停、恢复、归档、取消归档集中修改有效任务，**批量状态变更阶段只保存一次索引**；没有实际变化时不写盘。
3. 保存失败时回滚本批内存修改，不提前取消正在执行的任务，也不提前调度恢复任务。提交成功后再执行取消与统一调度。
4. 批量删除保留可恢复的两阶段流程：先统一保存 `removing`，再清理可立即删除的文件，最后统一保存删除结果。正在下载/转换的任务继续通过原有完成回调清理。
5. 删除失败或最终索引提交失败时保留可重试记录，不把已发生的文件删除伪装成成功回滚。
6. 本轮不拆分整个下载管理器的全局锁设计；先消除批量循环中的重复全量写盘。调度启动、在途任务完成仍可有必要的独立写入，**不承诺整个下载生命周期只有一次写盘**。

**文件：**
- [app_download_collections.go](<E:/Github Local/fluguo/native/core/app_download_collections.go>)
- [app_downloads.go](<E:/Github Local/fluguo/native/core/app_downloads.go>)
- 新增 `native/core/app_download_batch_test.go`，必要时复用现有下载测试辅助方法。

**验收：**
- 500 个已完成任务归档，批量状态提交一次，而非 500 次。
- 无变化操作不写盘；重复 ID 不重复处理。
- 覆盖部分无效任务、5000 项恢复上限、取消、保存失败回滚、删除失败、重启恢复。
- 原有续传和转换 pending 恢复逻辑保持不变。

### P2. 恢复配置导出移出 UI 主线程

**当前问题：** [recoveryFiles](<E:/Github Local/fluguo/lib/local_file_store.dart:374>)同步遍历和读取文件，累计可达 64MiB；随后还在主线程进行 JSON、UTF-8 编码及额外字节复制。

**实施方式：**

1. 主线程只做导出资格检查，截取允许导出的 SharedPreferences 值和存储目录路径。
2. 将目录扫描、受限读取、容错 UTF-8 解码、恢复 JSON 组装及最终字节编码交给后台 isolate。
3. isolate 只接收可传递的数据快照和路径，不捕获 `LocalStore`、插件实例或界面对象。
4. 返回最终字节供文件选择器保存，避免把大字符串传回主线程再编码、再复制。
5. 保持恢复文件格式、原始文本保留规则、不跟随符号链接、单文件 16MiB/累计读取 64MiB 的限制；错误如实上报，不覆盖损坏原文件。
6. 沿用恢复页现有 `_busy` 和禁止重复点击行为，不增加新的 UI 样式、弹窗或虚假的百分比进度。文件选择器继续在主 isolate 调用。

**文件：**
- [local_file_store.dart](<E:/Github Local/fluguo/lib/local_file_store.dart>)
- [local_store.dart](<E:/Github Local/fluguo/lib/local_store.dart:1842>)
- [backup_actions.dart](<E:/Github Local/fluguo/lib/ui/settings/backup_actions.dart:81>)
- 新增纯 Dart 导出 worker 文件 `lib/recovery_export.dart`。
- 更新恢复导出相关测试，新增 `test/recovery_export_test.dart`。

**验收：**
- 正常、损坏文本、`.bak`、大小上限、读盘失败及取消保存均保持预期行为。
- 主调用链不再同步扫描/读文件，也不执行整份恢复数据编码。
- 通过对最终 JSON 的解析比较验证格式兼容，不以“文件大小缩小”作为目标。

### P3. 下载总览改为自适应轮询

**建议采用固定策略，不额外增加设置项：**

| 状态 | 刷新策略 |
|---|---|
| 有排队、下载、转换或移除中的任务 | 每 2 秒 |
| 空列表，或只有完成/暂停/失败任务 | 每 10 秒 |
| 新建任务、恢复/暂停/删除/归档等操作完成 | 立即请求刷新 |
| 应用重新进入前台、切换用户、重新获得权限 | 立即请求刷新 |
| 应用不可见 | 停止前台总览定时器，后台下载服务不变 |
| 请求失败 | 2/4/8/10 秒有上限重试，成功或用户操作后重置 |

**实施方式：**

1. [DownloadOverview](<E:/Github Local/fluguo/lib/download_overview.dart>)用单次定时器按最新状态安排下一次刷新，不保留固定 2 秒空转定时器。
2. 仓库增加轻量下载变更通知，由改变下载状态的调用触发，读取下载列表本身不触发通知，避免刷新循环。
3. 在途刷新期间收到明确变更事件，合并为最多一次后续刷新，避免丢事件或并发重复请求。
4. 前后台切换与销毁释放定时器和监听；继续使用用户代次隔离旧响应。
5. **不按下载页是否可见暂停总览**，因为 [DownloadConverter](<E:/Github Local/fluguo/lib/download_converter.dart>)依赖它启动转换。转换和移除状态始终按快周期刷新。
6. 不改 Android 后台下载服务的 2 秒调度和通知策略。后台 isolate 的变化通过前台恢复刷新或低频兜底发现，不假设内存通知能跨 isolate。

**文件：**
- [download_overview.dart](<E:/Github Local/fluguo/lib/download_overview.dart>)
- [core_bridge.dart](<E:/Github Local/fluguo/lib/core_bridge.dart>)：下载状态变更通知及相关操作出口。
- [download_overview_test.dart](<E:/Github Local/fluguo/test/download_overview_test.dart>)、[download_converter_test.dart](<E:/Github Local/fluguo/test/download_converter_test.dart>)、[core_bridge_test.dart](<E:/Github Local/fluguo/test/core_bridge_test.dart>) 与必要的假仓库支持。

**验收：**
- 稳定空闲且无事件时，理论轮询频率从每分钟约 30 次降至约 6 次；这仅是请求次数推算，不是 CPU/耗电实测。
- 新任务不等待 10 秒空闲周期；转换不中断、不漏启动。
- 覆盖快慢切换、错误退避、前后台、用户切换、刷新合并、销毁清理。
