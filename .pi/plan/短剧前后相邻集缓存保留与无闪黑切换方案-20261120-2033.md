# 目标

在同一部短剧内保留 **上一集 / 当前集 / 下一集** 的播放计划和有界视频缓存，解决 `第2集 → 第3集 → 第2集` 每次都重新解析、重新缓存的问题，同时延续已准备画面的直接切换，防止连续观看导致缓存无限增长。

本轮为规划，未修改项目文件，未执行新的编译或测试。

## 一、现状与原因

已核对当前实现：

- `lib/playback_session.dart` 的 `_swap()` 在切到下一集后，对原当前集执行 `stop()` 并释放 `previousPlan.session`。
- native 的 `nativeReleasePlayback → nativeRelease → clearAssets` 会随之清理视频缓存，所以切回上一集只能重新加载。
- `PlaybackPreloader` 只保留一个下一集结果；`PlaybackHandle` 目前只有当前、备用两个播放器，不能同时保留前后两集的解码现场。
- Go 的 `nativePreloadLimit` 是一次预取最多 **8 MiB**，不是所有缓存的总上限。正常播放流多数直接转发，也不能认为已经看过的所有数据都缓存下来了。

因此，不能只删除 `release()`：那会保留越来越多的会话，也不能解决双向首帧准备问题。

## 二、建议行为：固定三集滑动窗口

| 当前集 | 允许保留 | 淘汰 |
|---|---|---|
| 第2集 | 第1、2、3集 | 窗口外全部 |
| 切到第3集 | 第2、3、4集 | 第1集 |
| 返回第2集 | 第1、2、3集 | 第4集 |

具体规则：

1. 第2集切第3集时，第2集改为暂停保留，不立即释放计划和 native 缓存；第3集接管原预载结果，只补缺失的第4集。
2. 返回第2集，优先直接使用其保留计划、缓存和已准备的视频输出，不重复 `resolve`，不重复下载命中的数据。
3. **保持当前行为：上下切集从头播放。** 离开的集先保存真实观看进度，再在后台暂停并定位到零点，准备回看首帧；这次后台定位不写观看记录、不触发自动下一集。
4. 跳到非相邻集时，按新目标重建窗口；只保留交集，先回收无关槽位再准备新邻集，不创建第四个播放器。
5. 第一集、最后一集只保留实际存在的邻集。换剧、换季、切用户、权限撤销、退出播放页会清理旧窗口。
6. 未看过的上一集也允许准备，但后台网络任务始终串行：用户当前目标优先，其次下一集，最后补缺失上一集；不影响当前集缓冲。

## 三、实现结构与文件范围

### 1. 统一管理三集资源所有权

新增 `lib/playback_episode_window.dart`，为窗口内每集保存：

- 完整身份：站源、剧 ID、章节原始标识/地址、集号、画质、在线/本地意图、用户会话代次。
- `PlaybackPlan`、取得时间、到期时间及准备状态。
- 对应播放器槽位、任务代次、串行操作队列和是否已释放标记。

修改：
- `lib/playback_preloader.dart`：从“单一下一集结果”改为服务窗口的有界调度，仍最多一个后台取流/预取任务；复用同身份在途请求，避免前后两套 preloader 互相取消。
- `lib/playback_session.dart`：集中处理角色轮换、接管、暂停复位和窗口淘汰；原先散落的 `clear/release/stop` 改为由窗口所有者决定。

每份计划只允许一个所有者。取消旧任务、迟到回包、失败回退、窗口移动时都必须恰好释放一次；不让过期任务重新填入窗口。

### 2. 有界播放器池，支持双向画面准备

修改 `lib/ui/player/playback_handle.dart`：

- 主播放器加两个邻集槽，**最多三个 Player/VideoController**，第三个按需创建。
- 槽位复用，窗口外播放器完成停止/清理后才能分配给新集；不按集数不断创建新控制器。
- 预开关闭时保留单播放器行为；电视等现有默认策略不变。额外解码器初始化失败或内存压力时降级到当前播放器加一个方向的预开，其余仅保留有界数据。

修改 `lib/ui/player/portrait_player_page.dart`、`player_video.dart` 及横屏使用的 `player_surface.dart`：

- 通过集号查询窗口中的播放器和准备状态，而不是只查询 `standbyIndex`。
- 保持前后邻页的视频层稳定挂载；当前角色变化不销毁已就绪的目标视频组件。
- 不改按钮、布局、手势方向、锁屏、状态栏、倍速或弹幕行为。

### 3. 把“缓存完成”和“画面就绪”分开

调整 `lib/ui/player/playback_video_ready.dart` 与会话交接：

- 明确区分：数据可用、媒体已打开、目标位置准备完成、输出可展示。
- 返回上一集时先暂停定位到零点，再确认本轮位置/输出状态；不能用残留末帧或控制器生命周期的一次性首帧 Future 证明新一轮已就绪。
- 已就绪相邻集直接交换，不重新打开媒体，不插入加载空白或淡入动画；同一时刻只有当前播放器允许播放声音。
- 尚未就绪时保留有界等待与正常回退，不以无限等待或播放旧画面伪装无缝。等待期间反向滑动、跳集、退出或切后台立即使旧意图失效。
- 实施中需要在 Android 上验证暂停 seek 后的输出信号；现有 SDK 首帧信号主要证明首次输出初始化，不能把模拟测试通过等同于所有机型逐帧无黑屏。

### 4. Go 侧缓存实际视频数据，不只缓存地址

主要文件：
- 新增 `native/core/app_stream_cache.go`：正文缓存预算、分块索引、去重和淘汰。
- `native/core/app_stream.go`：正常播放流读取时，顺带保存预算内的起播/回看数据，缓存命中直接返回。
- `native/core/app_preload.go`：预取与正常播放共用同一缓存和预算，避免重复保存同一字节。
- `native/core/app_stream_assets.go`：缓存更新、资源失效、关闭时配套调整计数，保持既有 HLS 资源租约保护。
- `native/core/app_playback_routes.go`：核验保留会话与窗口释放的关系，不通过提高现有会话数上限解决泄漏。

缓存策略：

- MP4 按有限区间/块保存，优先保留起播所需头部及容器索引数据，再保存预算内最近读取块；未缓存区间仍从上游读取。
- HLS 保留有限的起播分片、初始化段、必要密钥和稳定点播列表；动态播放列表继续遵循现有刷新规则。
- 正常媒体边读边转发，缓存旁路捕获，不为了缓存整段而阻塞首帧，不把整个文件 `ReadAll` 到内存。
- 继续检查 Range、Content-Range、ETag/Last-Modified、响应类型和错误正文；不能将不同版本的片段拼接，也不能把 200 错误页缓存成视频。
- 密钥和授权数据只留在受控内存会话，不落盘、不写日志；跨授权刷新不盲目复用旧分块。
- 复用现有 plan/release 通道，不增加用户设置，不引入永久下载目录或磁盘缓存。

## 四、容量与释放规则

| 资源 | 建议限制 |
|---|---|
| 剧集窗口 | 最多3集 |
| 播放器/视频控制器 | 最多3套，按需创建，降级模式更少 |
| 后台网络准备任务 | 最多1个；已取消但尚未结束的任务不允许无限堆积 |
| Go 缓存正文 | 每集最多8 MiB，播放器缓存池合计硬上限24 MiB |
| Go 待提交缓存块 | 分配前预留预算，与已缓存正文共同计入24 MiB |
| 播放器 demux 缓冲 | 当前集32 MiB，非当前集各4 MiB；显式限制后向缓冲、禁用额外磁盘缓存 |
| 邻集播放计划 | 沿用保守2分钟有效期，并受上游授权到期时间减5秒限制，不通过来回切集无限续期 |

说明：**24 MiB 是 Go 正文缓存硬上限，不是整个应用内存上限。** 播放器缓冲配置合计约40 MiB，解码器、GPU纹理、Flutter画面及短时网络缓冲还会另外占内存；不能声称整个 App 严格小于64 MiB。验收同时检查缓存计数、播放器数量和长时间切集后的进程内存趋势。

淘汰与降级：

- 窗口外资源立即标记失效；取消任务并按槽位顺序释放，不等待自然过期。
- 达到字节预算时优先淘汰非必要、最久未使用的正文块，不删除当前播放必需的资源索引；缓存不足不阻断正常流式播放。
- 进入后台或暂停超过现有1分钟阈值：取消邻集准备、释放邻集解码器和缓存，当前集保持原有后台播放规则。
- 在 `lib/ui/player/playback_page.dart` 接入内存压力通知：优先回收非当前集资源，本次会话限制恢复速度，避免刚释放又立刻创建。
- 退出/换用户/权限变化全部清理；剧场交还只转移当前现场，其他槽全部释放。

## 五、验证与验收

### Dart/Flutter

新增窗口管理测试，并扩展现有：
- `test/playback_preloader_test.dart`
- `test/playback_preload_integration_test.dart`
- `test/portrait_preload_surface_test.dart`
- `test/playback_video_ready_test.dart`

覆盖：
1. `2→3→2` 和 `3→2→3` 在有效缓存命中时不重复解析、不重建视频组件。
2. `2→3→4` 淘汰第2集，连续切100集以及反复往返时最多3个槽位/播放器。
3. 原来直接打开、并非预载进入的第2集，其正常播放数据也能在切回时命中。
4. 预开关闭、低资源降级、短期授权过期、画质变化、本地/在线切换均正确隔离。
5. 等待首帧时滑回、快速跳集、退出、切用户、后台和睡眠不会造成串集、迟到回填或双重声音。
6. 后台准备上一集不会覆盖观看历史，也不会触发自动连播。

### Go

新增缓存预算/区间命中测试，扩展 `app_preload_lifecycle_test.go`、`app_preload_budget_test.go` 和流缓存测试：
- 已缓存区间断开上游后仍可读；未缓存区间正常回源。
- 三会话并发、超大响应、取消读取、重复Range、HLS动态列表和错误正文均受预算约束。
- 已释放会话不接受迟到回填；缓存与在途预留计数最终归零。
- 当前集不被邻集准备或淘汰误释放。

### 实际检查

- 使用已有便携工具链运行定向 Flutter 回归、静态分析及完整 Go core 测试；支持时加 Go race 检查。
- 真实红果样本跑 `2→3→2`，记录缓存命中、上游请求次数和实际字节数，日志脱敏。
- Android 实机录屏检查第一次向前、第一次向后、连续往返和快速撤回，验证没有新引入的黑帧、错帧或双重声音；长时间切集核对内存趋稳。
- 无实机时明确报告未验证项，不以 mock 首帧测试宣称所有手机绝对无黑屏。

## 六、范围与预期边界

- 不改 UI 外观、站源签名、下载管理或观看记录语义。
- 优先保证**同剧相邻集、计划有效且目标画面已就绪**时直接切换。
- 固定预算意味着保留的是有界视频数据，而非任意大小三集的完整离线副本。超出缓存范围、授权过期、内存压力降级或设备解码能力不足时仍可能补网络/等待画面，但不能无限增长或打断当前集。
