本路线图替代此前版本，并融合 source/ 当前工作区的源码对照（第 9 节）。目标：保留根工程现有功能、数据兼容和 UI 风格，通过实测减少不必要工作；允许有证据支持的体验改善，不因“统一”或移植参考代码而改变已经正常的外观。

**执行依据：第10节为最新逐项评估，优先于前文候选顺序或早期建议；第3—9节保留背景与对照证据，不代表批准实施。全部项目均等用户明确授权后才可改代码；本机无编译环境，静态通过不等于运行验收通过。**

- 当前基线：提交 `7168315`（DC105），`pubspec.yaml` 为 `1.0.55+155`。本轮只修改本文件，不改业务代码、测试、依赖、CI、版本和更新日志，不执行提交或推送。
- 本轮重新检查 PATH：未找到 Flutter、Dart、Go；Python 可用。源码核对和文档检查已执行，编译、分析器、应用测试、构建、运行时性能和截图对比未执行。

## 2. 必须保留的约束

1. 保留默认主题下的颜色、透明度、模糊、描边、阴影、圆角、字号、间距、按钮位置、层叠顺序和现有动效参数。合理差异不按缺陷处理。
2. 保留播放、换集、拖动、倍速、预开、定时停止、全屏、PiP、后台切换与用户撤权的现有语义；特别保留 Video/Texture 挂载与同一播放器交接。
3. 保留存储字段、迁移、备份格式、权限、写入队列、异常重试及原文件保护；不可把超时当成原生进程已退出。
4. 保留导航栈、返回仲裁、滚动位置、筛选、多选、焦点和输入能力。
5. 改善允许沿用现有风格解决可复现的裁切、卡顿、误触或可访问性问题。静态推断不足以说明“更好”，要有前后对比和交互回归。收益不明确时保留原样。
6. 每个改动按最小完整范围隔离，必要时可以跨文件；不要求强行单文件，不自动提交。实现阶段的授权不等于获准发布、推送或删除参考工程。
7. 优化、缺陷修复、视觉改善、新功能分别验证；不得为了证明优化有效而把既有行为断言改宽或删除。

## 3. 本轮发现并撤回的错误规划

### 3.1 原生输入文件不是死代码，禁止删除

源码已确认：`lib/ui/widgets/search_field.dart:4` 导入 `../../native_text_input.dart`，`:123` 调用 `NativeTextInput.stop()`，`:146` 调用 `start()`。`lib/native_text_input.dart:3-31` 提供真实 MethodChannel 交互。

结论：撤回“零引用、可以删除”的判断，保留文件和调用链。即使某个平台没有实现 channel，也不能据此删掉 Dart 调用方。

### 3.2 退出重试是文件占用保护，不能限次后放行队列

源码已确认：

- `lib/media_pipeline.dart:277-298` 的 `FFmpegExecutor.waitForIdle()` 单次等待已有超时；`:294` 明确表示“尚未确认退出，文件可能仍被占用”。它不是 FFmpegKit 提供的同名 API。
- `lib/download_converter.dart:163-179` 在退出未确认时设置 `_retiring`，保留原文件；`:212-231` 重试确认退出和提交取消，成功后才清除保护。
- `lib/download_merge.dart:160-180` 在确认退出后处理延迟清理；`lib/merge_queue.dart:315-362` 通过 `cleaning`、`_retiring` 与 work lease 保留占用；`:227`、`:248` 阻止保护期间启动后续任务。
- `test/media_pipeline_test.dart:478-496` 明确验证“超时不假成功”；`test/downloads_management_test.dart:761-800` 明确验证“原生退出前禁止删除原分集”。这些是现有测试源码，未在本机运行。

撤回：不能固定重试 10 次后清除 `_retiring`、释放 lease、允许删输入或继续共享资源任务。取消等待也不代表取消成功，更不代表原生停止访问文件。

状态：保留现有保护，归 IV 类。后续若要降低持续重试成本，必须设计“退出未确认／已退出但提交失败／清理待重试”状态，保留占用与可恢复工作；只能在获得退出证据后执行清理。不能把当前等待直接认定为确定性死锁或 P0。

### 3.3 弹幕位置变化本身就是必要通知

`lib/danmaku_controller.dart:126-159` 更新位置、时长与状态；`:161-168` 是重置运动锚点的条件，并非所有 UI 变化的判断。`lib/ui/player/danmaku_overlay.dart:204-207` 直接用 `positionMs` 决定弹幕进入和退出。

撤回：不能仅用 drift/jumped/visible/moving/rate 的变化决定通知，否则可能漏出弹幕、漏退场。

候选：只对完整的可观察状态完全相同的调用去重，仍执行必要的窗口加载与取消逻辑；或单独设计调度与运动通知。但要先覆盖跨入场时间、跨退场时间、暂停、缓冲、倍速、seek、时长变化、窗口加载、屏蔽词及可用性变化。未完成前保留原通知。

### 3.4 焦点框优化缺少失效依据，暂缓

`lib/ui/widgets/focus_ring.dart:270-283` 通过 post-frame 回调采样，`:280` 已有 `_motion.isAnimating || target._outline != null` 条件；该 State 的字段见 `:203-208`，没有此前方案中的 `_dirty`。

撤回：不能直接改成 `_motion.isAnimating || _dirty`，也不能假定每帧回调必然主动产生新帧。是否需要持续采样、如何在滚动／布局／变换／窗口变化后失效，尚未建立完整证据。保留现实现，先做性能采样与焦点跟随回归，再决定是否优化。

### 3.5 保存进度已有去重，不再重复规划

`lib/playback_session.dart:1149-1184` 已使用 `_savedProgressKey`、`quiet`、`_savedQuietly` 去重，处理保存失败重试及警告；`:68-71` 定时调用 `saveProgress(quiet: true)`；`:1135-1139` 切后台暂停并主动保存，`:1188-1189` dispose 也主动保存。

撤回：不改 5 秒保存与健康检查策略，不增加简单“暂停则不存”或“只前台保存”条件。前两版对后台持续播放的概括不准确，实际行为取决于调用方生命周期与 PiP 适配。后续必须按实际入口验证，而非假定。

### 3.6 封面队列有明确节流和后入先出顺序

`lib/cover_loader.dart:35` 延迟 150ms，`:44-48` 延迟后入队，`:54` 用 `removeLast()` 优先处理后来入队的任务，并发上限为 6。

撤回：帧回调不能等价替代 150ms Timer；换容器时也不能改为先进先出。保留节奏与顺序，只在 profiling 证明队列操作有实际成本后，考虑保持身份、取消、顺序及并发语义的数据结构优化。

### 3.7 FFI 差异不等于应删除协议能力

`cachedRecommendations` 在 `native/core/app_runtime.go:411-412` 是已实现的协议入口；其实现还被 `native/core/app_recommendations.go:43/48` 内部调用。当前 Dart 没发送此 action，不能证明原生入口是应删除的死分支。`lib/core_bridge.dart:718-724` 的 `lan` 是授权策略中的遗留条件，并非已证实发生的错误请求。

改为：建立“Dart 实际发送 actions 是 Go 支持 actions 的子集”的契约测试；允许显式记录原生独有能力，单列策略表遗留项，不要求字符串集合严格相等。不能把所有字符串字面量计数当 action 数，也不能直接删 `cachedRecommendations`。枚举后仍须保留线上的原始字符串。

### 3.8 权限结论被扩大，现有证据不足以确认权限漏洞

`native/core/app_build.go:38-65` 主要检查版别和站源／章节一致性，不是完整的用户授权系统。`lib/core_bridge.dart:725-766` 有用户、站源和下载权限检查。`native/core/app_runtime.go:448-452` 的 `DownloadIdentity` 校验以及 `:460-462` 的 normalization identity 参数，不等同于用户登录凭据。

仅凭一个 switch 没有覆盖所有 action，不能认定整个 Go 核心完全不校验，也不能照搬 identity 字段当权限方案。`finishConversion`、`finishNormalization`、`workLease end` 在 Dart 侧有明确放行条件，撤权后的安全收尾必须保留。

状态：先梳理 UI、后台下载、FFI 与文件占用的信任边界，不改授权，不新增无需求的逐请求日志。若需要日志，沿用现有调试开关，不记录 URL、Cookie、签名或凭据。

### 存储写序列的准确要求

`local_file_store.dart:385-396` 实际顺序：写 `.tmp` 并 flush → 若需备份则复制现主文件为 `.bak` → 删除现主文件 → rename `.tmp`。不是“先替换再备份”。

`commit()` 的完整顺序还包含：先写 `transaction.json` → 写各类别 → 必要时写 initialized → 删除事务日志 → 更新内存；事务已准备后出错要保留恢复状态。编码移动不得改变这些步骤、失败边界和启动重放能力。

## 5. UI、动画与架构的处理范围

### 保留现有样式，不机械统一

- 不因圆角、遮罩浓度、进度条、Slider、标题或卡片存在多种数值就判为缺陷。各控件用途不同，差异可合理存在。
- 暂不批量换玻璃 preset，不把全部 AlertDialog、SnackBar 强制换形态，不换详情页选集网格，不修改现有 duration/curve/缩放/位移/透明度。
- 修正文档使之准确反映当前 `AppMotion` 即可。显式滚动时长可按交互用途保留；不再把 250ms 机械改成 200 或 360ms。
- `smooth_scroll.dart` 的 easeInOutCubic 与 `AppMotion.navigationCurve` 的 Cubic(0.2,0,0,1) 并非相同曲线，禁止以“去重复”名义互换。
- `IndexedStack` 外包 Offstage 不会自动免除子树布局；不能把它当成已证实的性能解决方案。保留导航结构。
- `gaplessPlayback` 可能在身份变化时保留旧图，不能默认断言改善；保留现封面占位和图片 key。

### 允许改善，但先证明问题

- 大字体布局：先在现有样式下复现裁切。`max(原高度, 测量高度)` 也不能先保证默认字号完全不变，必须按实际字体、行高、padding、约束和窗口验证，且同步浮栏占位与滚动布局。
- 命中区域：外加 padding 可能改变布局；HitTestBehavior 不能扩大 RenderBox 之外的命中范围。需要在已有约束内设计，保证不侵占相邻控件／滚动手势／系统手势区。
- Semantics：ExcludeSemantics 会改变读屏体验，不是“只有视觉不变就安全”。只对确认装饰性的元素排除，保留播放状态、进度、错误和必要操作提示。
- Ticker 自动滚动：必须按 elapsed 换算位移，覆盖 60/90/120Hz、暂停、边界、拖选与 dispose；不按帧数固定步长。

### 架构候选

保持 ChangeNotifier 和现有外部 API。LocalStore 依次拆设置、用户、备份、历史、收藏仅作为候选，不一轮拆完；保留通知时机、事务队列、权限与磁盘格式。文件移动本身不必然改变生命周期，风险来自提取后的依赖、所有权和构造方式，不能凭目录位置判定。

详情页拆 widget 要核对 key、State 边界、Inherited 依赖、焦点和布局约束。删除规则提取需保留二次权限检查、合并／导出占用保护和原提示；不同提示可能对应不同检查阶段，不因文案不同就认定逻辑已分叉。

AppScope 增 store、分页抽象与 categoryFamily 字段都不是必须立即完成的优化。消费新增分类字段可能改变分类、过滤和推荐结果，需单独做语义兼容测试；不承诺“新增字段所以零行为”。

## 6. 修正后的实施顺序

下面是先后顺序，未授权开始业务实现。版本号仅在实际实施时按当时基线递增，不预占 `1.0.56` 至 `1.0.60`。

### 阶段 1：建立可运行的基线

1. 在有 SDK 的环境运行下节检查，记录真实结果。已有失败不能先假定存在，也不能通过改宽断言变绿。
2. 修正文档中过期的动效参数；评估 analyzer 对 source/live 嵌套工程的实际作用域，再决定是否补 exclude。保留这两份参考工程，不执行 git rm。
3. 为拟优化点补特征测试，优先原生退出占用、弹幕时间边界、Store 通知依赖、用户切换和存储恢复。

### 9.11 S8：DNS回退与可重放请求（专项评估，暂缓）

#### E10（播放页局部重建）评估结论：不做

现状：`PlayerSurface.build` 的 `ListenableBuilder(listenable: session)` 包住整个 `Stack`（视频、弹幕、加载/错误/暂停层、手势、播控）；另有 `:105-117` 对 position/buffer 的 `setState`。

改动只有一种形态：把 builder 收窄到播控子树。影响面：

1. `Stack` 子项顺序即遮挡关系，错一格就变成弹幕盖控件或错误层被视频挡住；
2. `PlayerVideo` 依赖 `ValueKey(session.player)` 与固定挂载时机（剧场的 `StablePreviewSurface` 要求 Video/Texture 始终挂载），移出 builder 可能改变 element 位置并重挂纹理，表现为首帧黑屏或预览闪烁；
3. `setState` 来自 State 自身、不在 builder 内，只挪 builder 并不能消除该重建，必须同时把进度订阅改为局部 widget；
4. 手机竖屏、全屏、小窗、电视四套布局共用同一 `Stack`，任一错位都要四端回归。

结论：收益是减少一次重建，代价是播放页黑屏/遮挡类故障，且无法在本机编译验证。建议在 S1（弹幕重建）实施并有等价测试覆盖后再评估是否仍有必要。

**`_applySkip` 的判据与理由**（每条都对应一种会被用户当成故障的情形）：

| 情形 | 处理 | 理由 |
|---|---|---|
| `_loading`／`_error != null`／`!_usable`／`_openedIndex != _index` | 直接返回 | 跳转必须有可用的当前集；加载中拖进度会被随后的 open 覆盖，出错时应留在错误界面 |
| `total <= 2s` | 返回 | 过短媒体没有片头片尾可言 |
| `_openedAt >= .5`（续播） | 不跳片头 | 续播进度本来就在片头之后，往前拽等于把用户送回广告段 |
| 已越过片头（含手动拖动） | 置 `_introSkipped = true` 后不再介入 | 只跳一次；拖动后仍反复跳回会被认为无法快进 |
| 片头区间 ≥ `total - 1s` | 放弃片头 | 避免一开播就被送到结尾 |
| 暂停（`!playing` 或 `!_playIntent`） | 不跳片尾 | 停在结尾的画面不该被后台替换 |
| `total - 片尾秒数 <= 片头秒数 + 1s` | 放弃片尾 | 区间重叠时以片头为准 |
| 命中片尾 | 跳到 `total - 300ms`，不直接跳 EOF | 交给既有 `_completed` 分支：定时停止照旧在片尾停下，自动连播照旧进下一集；同时不会触发 `early_completion` 误判（该判据是 `duration - 2s`） |
